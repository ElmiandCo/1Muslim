## The three final plans (USD, automatic renewal)
| Billing cadence | Actual recurring charge | Marketing copy |
|---|---|---|
| Weekly | $5.99 every week | **Flexible access** |
| Monthly | $9.99 every month | **Everyday value** |
| Yearly | $35.00 every year | **HOT DEAL · BEST VALUE · SAVE 71%** |

**Math for consumer copy:** $9.99 × 12 = $119.88. $119.88 - $35.00 = **$84.88/year saved** by choosing annual instead of twelve monthly payments. $84.88 / $119.88 = **70.803%**, rounded to **71%**. Annual equivalent $35 / 12 = $2.9167 ≈ **$2.92/month**. All comparison disclosures must clearly identify the comparison plan and duration. Do not compare to 52 weeks without labeling the 364-vs-365-day difference. No fake limited-time countdown or unsupported “exclusive” claims.

Do not create three different products unless the actual business model requires distinct benefits. Keep legacy monthly price object and existing live subscriptions unchanged. **Phase A — build v3.9 first:** This branch implements UI selection, server price validation, webhook matching for three plans + legacy, and safe checkout-disabled display. Merge only after CI/security/preview smoke. Do NOT block unrelated v3.9 on unavailable new Stripe keys.

**Phase B — AFTER v3.9 production as owner requested:** identify the intended **correct LIVE Stripe account**; create or reuse the Unlocked product and **three verified recurring USD live prices**. Set these production Vercel environment variables; env values never belong in GitHub commits:

**Never** use `NEXT_PUBLIC_` for Stripe secret keys. Preserve `STRIPE_UNLOCKED_PRICE_ID` for existing legacy subscriptions/webhook reconciliation while any member is on it; do not use that old Price ID for v3.9 new purchases.

**Phase C — activation checks:** redeploy the new Vercel config after adding env variables. `GET /api/stripe/pricing` returns `configured: true` only if three different price IDs and required server credentials are provided; it reveals no secret or Price IDs. Server checkout requires `?plan=weekly|monthly|yearly` and independently checks Stripe active=true, amount/currency/recurrence before opening any Checkout Session. It rejects legacy/trial query fallback. If environment not ready, user sees the new plan cards and an informational disabled CTA, not a failing or misleading pay button.

## Smoke checklist
1. Guest sees yearly featured savings with exact math, checkout requires login.
2. Before IDs configured: all plans shown, checkout disabled; previously active subscribers can still reach Billing Portal.
3. With live IDs configured: each plan opens a legitimate Stripe Checkout Session only for the correct amount/frequency.
4. Mismatched, missing, inactive, swapped, cross-mode or duplicated price IDs produce safe checkout rejection; never silently use $3.99.
5. New and legacy checkout webhooks associate current Stripe price and update RLS-protected unlocked_subscriptions. Cancellation and past-due transitions observed through webhook signature verification.
6. Existing subscribers on legacy plan remain on their billing agreement. Billing Portal must not automatically migrate them.
7. Mobile Safari 320–430px and desktop: selectable cards, visible selected state, voiceover labels, disabled CTA, font contrast, no overflow.
8. No production success announcement until Vercel READY and payments verified. A webhook or env error must not trigger false ‘passed’ admin DMs.
